# 07 · 实验结果与准出评审报告（含外部 Review 校准与边界声明）

> 本文档汇总 Phase 2（纯 Go 离线检索、缓存仿真与敏感性/校准实验）与 Phase 3（DeepSeek-Chat 端到端生成 + 三层盲评）的实测结果，并针对外部评审指出的 5 项可信度问题逐项补充验证与结论降级说明。  
> **基准集规模**：28 个正式合成基准用例（Suite A 6 个、Suite B 11 个[含 5 个无显式关键词对抗用例]、Suite C 6 个、Suite D 5 个，共 29 个探针）。

## 2. 关键词泛化对抗测试（揭示 `0%` 污染率的真实边界）

为检验 `HeuristicExtractor` 是否依赖显式中文触发词（`"废除"`, `"改用"`, `"禁止"` 等），新增 5 个**无任何显式关键词的口语化变更对抗用例**（[`suite_b_07`](../datasets/suite_b_07_implicit_db_revert.json)–[`suite_b_11`](../datasets/suite_b_11_implicit_retry_policy.json)），对比 `--extractor heuristic` 与 `--extractor oracle`：

| 模式 | 原 6 个显式用例 `Suite B Contam%` | 加入 5 个隐晦用例后（11 个）`Suite B Contam%` | 说明 |
| :--- | ---: | ---: | :--- |
| `--extractor heuristic` | 0.0% (0/7) | **41.7% (5/12) [FAIL]** | 5 个隐晦表达变更用例**全部穿透失败** |
| `--extractor oracle` | 0.0% (0/7) | **0.0% (0/12) [PASS]** | 状态机机制本身在准确事件输入下保持零污染 |

> **结论降级声明**：  
> 此前“0.0% 污染率”仅在“存在显式关键词或准确账本抽取”的前提下成立。**在开放式自然语言对话中，纯正则启发式账本抽取器不可靠，绝不能直接用于生产。** 合入 `gp` 时，`ContextLedger` 必须由 **Agent 显式工具调用或压缩阶段的结构化 LLM 提取** 来维护，而非中文关键词正则。

## 3. `Epoch` 敏感性曲线（`8 / 12 / 16 / 24 / 32`）

为验证 `Epoch = 16` 并非对 5 个 `Suite D` 用例过拟合，在 23 用例上对 `Epoch = 8, 12, 16, 24, 32` 做单变量扫描（诚实 `B1` 在同一口径下保持 `D-Cache% = 40.1%`, `D-CostDp = -5.4%`）：

| Epoch | `E4-A` TokDrop | `E4-A` D-Cache% | `E4-A` D-CostDp | `E4-B` D-Cache% | `E4-B` D-CostDp | `E4-A` p95(ms) |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 75.3% | 69.9% | 40.6% | 42.9% | -0.8% | 0.38 |
| 12 | 75.9% | 75.0% | **52.2%** | 63.9% | 36.5% | 0.40 |
| **16** | 73.3% | 78.9% | **52.3%** | 71.9% | 41.2% | 0.44 |
| 24 | 66.9% | 82.9% | 45.8% | 78.1% | 35.8% | 0.52 |
| 32 | 61.4% | 85.9% | 41.2% | 82.0% | 31.2% | 0.63 |

- **U 型帕累托平台**：`Epoch` 在 `12–16` 区间形成稳定收益平台（成本降幅 `52.2%–52.3%`）；过小（`8`）会因频繁重建工作集击穿缓存，过大（`24–32`）虽然命中率更高，但近期窗口过肥导致总 Token 降幅从 `75.9%` 跌至 `61.4%`，账单反而回升。
- **拼接顺序优势稳健**：在全部 5 个 Epoch 档位中，`E4-A` 均一致性优于 `E4-B`（Suite D 缓存命中高 `+3.9pp` 至 `+27.0pp`，成本降幅高 `+10.0pp` 至 `+41.4pp`）。

## 4. 自制 Tokenizer 与真实 DeepSeek Token 偏差校准

利用 Phase 3 实测留存的 **120 次真实 `deepseek-chat` API 请求**（来自 `reports/e2e_deepseek.json`），直接对比 [tokenizer.go](../internal/tokenizer/tokenizer.go) 的估算值与服务端返回的 `usage.input_tokens`：

- **总体累计总量**：估算 `494,177` vs 真实 `508,072`（整体比值 **`0.973x`**）
- **单条中位比值与误差**：中位比值 `0.969x`，中位绝对相对误差 **`9.2%`**
- **尾部误差警告**：均值比值 `1.210x`，平均相对误差（MAPE）**`29.2%`**，**p95 相对误差高达 `111.3%`**（在短中文提示词上，按“1 汉字 = 1 token”显著高估了真实 BPE 合并后的 Token 数）。

> **修正要求**：离线模拟的 `TokDrop` 与 `CostDrop` 存在上述 Tokenizer 尾部估算误差，合入 [`gp`](https://github.com/npc1607/gp) 后应以生产模型真实返回 `TokenUsage` 或精确 BPE 分词器为准。

## 6. 审慎的准出建议（合入 `gp` 的分步路径）

**总体结论**：**机制方向验证成立，但当前合成数据集（28 用例）与启发式抽取器不足以一次性把全套复杂图算法直接合入 `gp` 主干。** 建议按最小风险分拆合入：

1. **首个合入 PR（最小高确定性收益）**：优先将 **L1 结构化 `ContextLedger` 状态机（[ledger.go](../internal/ledger/ledger.go)）+ `Epoch=12~16` 冻结掩码 + `E4-A` 拼接顺序 + 只读回查工具** 迁入 `gp`，并用 `gp` 原生 `callLLMSummary` 的结构化 JSON 输出模式维护账本（不使用本实验的中文正则启发式）。
2. **第二阶段 PR**：在 `gp` 真实脱敏长会话回放集（`gp.db`）上跑通诚实 `B1`（真实 LLM 摘要）对照后，再决定是否引入 `PPR + ACT-R + Budgeted MMR`。
