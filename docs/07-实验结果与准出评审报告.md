### 关键消融发现
1. **Epoch 步长调优（`epoch=8` vs `epoch=16`）**：在 Suite D 长会话回放中，将 `Epoch` 从 8 轮调整为 16 轮后，`E4-A` 的 Suite D 缓存命中率从 `69.9%` 提升至 **`78.9%`**（`B1` 仅 `36.4%`），Suite D 含缓存总账单降幅从 `40.6%` 提升至 **`52.3%`**。
2. **为什么 `E4-A` 缓存命中率显著高于 `E4-B`？**  
   当 `WorkingSet` 在同一 Epoch 内冻结复用时：
   - **`E4-A`**（`[System + Ledger] → [WorkingSet] → [EpochRecentWindow]`）将高频窗口置于末尾，每次新增轮次严格追加在序列尾部，前缀保持完全一致；
   - **`E4-B`**（`[System + Ledger] → [EpochRecentWindow] → [WorkingSet]`）由于 `EpochRecentWindow` 不断追加新轮次，导致后置 `WorkingSet` 的字节偏移每轮后移，从而反复击穿尾部缓存。
3. **计算延迟与算子对比**：`PPR`（`p95 = 0.41 ms`）与 `HeatKernel`（`0.71 ms`）召回率持平但前者快近一倍；`Budgeted MMR` 较 `k-DPP` 在多跳与稀疏短约束保留上更稳定，远低于 `30 ms` 延迟红线。

## 4. 准出结论与 Phase 4 合入建议

**评审结论：GO（建议合入 [`gp`](https://github.com/npc1607/gp) 主干）**

推荐直接采用 **`E4-A`（`Epoch = 16`）** 架构迁移至 [`gp`](https://github.com/npc1607/gp) 的 `internal/core/compaction` 与 `internal/agent`：
1. **L1 结构化约束账本（`ContextLedger`）**：以 Canonical 确定性序列化存根替代 `callLLMSummary` 的自由文本摘要，附带 `provenance`（`entry_id`）及 `active` / `superseded` 状态机；
2. **L2 权重工作集选择器**：`CodeTokenize BM25 + 异构图 PPR（α=0.75, β=0.4）+ Dense RRF + ACT-R 幂律遗忘（d=0.5）+ zlib 密度惩罚 + Budgeted MMR（λ=0.6, η=0.5）`；
3. **L3 前缀缓存友好编排**：用 `Epoch = 16` 冻结观测掩码替换逐轮滑动掩码，按 `[System + Tools + Ledger] → [Epoch-Frozen WorkingSet] → [Append-Only RecentWindow] → [Query]` 拼接，并对接 Anthropic `cache_control` 断点及只读回查工具（`recall_entries` / `search_session_history`）。
