# 04 · 实验设计与评测基准

> 本文档定义可重复执行的离线与半在线实验方案，用于在**正式改造 [`gp`](https://github.com/npc1607/gp) 主循环之前**，用客观数据回答以下核心工程问题：
> 1. **PPR + 图索引** 能否真正捞回“表面无关但多跳关联”的历史信息？
> 2. **MMR / k-DPP** 相比纯 Top-K 能在高冗余对话里抢救回多少关键前提？
> 3. **结构化约束账本 + ACT-R 幂律衰减** 能否根治自然语言摘要的约束遗忘与冲突污染？
> 4. **哪种 Prompt Caching 拼接顺序 & 掩码冻结策略** 真实账单最低、准确率最高？
> 5. **裸 Surprisal（$-\log P$）** 在真实数据上到底有多坑？（用负对照数据实锤验证）

---

## 1. 测试数据集设计（4 类“照妖镜”评测套件）

所有用例统一采用 [`datasets/case.schema.json`](../datasets/case.schema.json) 描述（参见示例 [`datasets/sample-multihop-case.json`](../datasets/sample-multihop-case.json)）。每条长会话设计为 **50–150 轮、原始累计 40k–150k tokens**，在最后设置多个待评测 **Probe（探针提问）**。

### Suite A：隐性多跳关联套件（测 PPR / 热核扩散）
- **构造方法**：故意保证源前提 $A$ 与末尾提问 $B$ **零关键词重叠、低语义余弦相似度（$< 0.25$）**，二者必须通过 2–3 跳中间实体（文件引用、模块依赖、错误码、配置项）建立连接。
- **典型用例**：
  1. 第 4 轮定下“构建机无外网 / GPU 显存预算上限” $\rightarrow$ 第 35 轮排查 Dockerfile / 部署 YAML $\rightarrow$ 第 90 轮问“直接拉取 HuggingFace 权重脚本能否上线”。
  2. 第 8 轮约定“某 protobuf 字段禁止复用旧编号 12” $\rightarrow$ 第 48 轮修改 `services/proto/...` 结构体映射 $\rightarrow$ 第 105 轮问“新增字段 tag 应该怎么分配”。
- **判定标准**：工作集必须成功召回第 4 / 第 8 轮的 `entry_id`，且模型最终结论明确引用该约束。

### Suite B：约束演进与状态冲突套件（测结构化账本 + 幂律衰减 + Provenance）
- **构造方法**：同一会话内多次**新增、推翻、修改**核心技术选型或路径约定，并在中间穿插大量不相关调试对话拉大时间跨度。
- **典型用例**：
  1. 第 10 轮“用 MySQL” $\rightarrow$ 第 55 轮“全量切换 PostgreSQL，彻底废除 MySQL” $\rightarrow$ 第 115 轮“编写分页和 JSON 字段查询 SQL”。
  2. 第 15 轮“接口认证走静态 Token” $\rightarrow$ 第 70 轮“改用 HMAC 签名” $\rightarrow$ 第 120 轮“写客户端请求中间件”。
- **判定标准**：**不得召回或采纳已作废（`superseded`）旧规则**；当用户追问“为什么第 55 轮改了架构”时，能凭借 `provenance` 指针回查原始原因不产生幻觉。

### Suite C：高熵噪音与复读机风暴套件（测 MMR / k-DPP & 反证裸 Surprisal）
- **构造方法**：在会话中段注入大量“高困惑度但无用”或“高复读但非关键”的内容：
  - 连续 8 轮贴入长 Go panic stack trace、混淆 JS、UUID、大段测试日志；
  - 连续 10 轮围绕某次小 typo 来回修改确认；
  - 在中间角落（如第 22 轮）埋入 1 条极短但决定胜负的前提（如“测试环境并发上限固定为 2”）。
- **判定标准**：工作集不被堆栈噪音或 typo 复读机塞满，成功在有限预算内保住第 22 轮关键前提。

### Suite D：真实 `gp` 长会话回放套件（测端到端缓存命中率与真实账单）
- **构造方法**：从本地 `.gp/gp.db`（脱敏后）抽取真实 Coding / 排查长轨迹，按 `turn = 1..T` 逐轮回放，记录每一轮发送的真实 `messages[]`、触发 `Compact` 的次数、以及逐轮前缀与上一轮的**最长公共前缀 Token 数（LCP Tokens）**。

## 2. 对照与消融实验矩阵（8 组配置）

为精准剥离每个数学工具的真实贡献，采用严格的单变量递进消融设计：

| 组别 | 上下文组装策略 | 重点检验假设 |
| :--- | :--- | :--- |
| **B0（天花板基线）** | **全量历史 + Prefix Caching**（不删减、不掩码，直到硬上限） | 给出准确率理论上限，并测算“全量 + 缓存”的真实账单基准线（验证多少轮以后才值得裁剪） |
| **B1（`gp` 现状基线）** | 复现 `gp` 当前逻辑：`applyObservationMasking(5)` + `0.80` 触发 `Compact`（5 段自然语言摘要） | 量化当前 `gp` 滑窗掩码每轮改变前缀造成的**缓存失效率**，以及自然语言摘要在 Suite B 上的漂移率 |
| **B2（朴素 RAG 基线）** | 近期 6 轮原文 + 纯向量 Cosine Top-K（无图、无去重、无账本） | 暴露纯语义检索在 Suite A（多跳漏召回）与 Suite C（复读机挤占）上的短板 |
| **E1（+ 去冗余）** | `B2` + **Budgeted MMR（$\lambda=0.6, \eta=0.5$）** vs **Budgeted k-DPP** | 对比 MMR 与 k-DPP 在 Suite C 的关键前提保活率、多样性及计算耗时（ms） |
| **E2（+ 多跳关联）** | `E1` + **异构实体图 + PPR（$\alpha=0.75$）** vs **热核扩散（$t=3.0$）** + **BM25 RRF** | 验证图扩散对 Suite A 隐性关联召回率的提升幅度，并横向对比 PPR 与热核 |
| **E3（+ 状态与遗忘）** | `E2` + **结构化 `ContextLedger`（含 Provenance）+ ACT-R 幂律衰减（$d=0.5$）** | 验证在 Suite B 中对已作废约束的抗污染能力，及长程反复提及约束的常驻准确率 |
| **E4（缓存布局仲裁）** | 在 `E3` 上开启 **Epoch 冻结掩码（Epoch=8 轮）**，对比两种拼接顺序：<br>• **E4-A**：`[基底] → [召回工作集] → [Epoch 高频滑窗 + Query]`<br>• **E4-B**：`[基底] → [Epoch 高频滑窗] → [召回工作集 + Query]` | **关键商业账单实验**：对比 E4-A 与 E4-B 的 `CacheReadRatio`、真实总花费 (USD) 与答案准确率 |
| **E5（负对照组）** | 在 `E2` 中注入 **裸 Surprisal（$-\log P$）权重** | 实证验证“高熵堆栈/UUID 被顶到最高优先级、挤掉有效上下文”的劣化幅度 |

## 3. 评测指标与计算口径

### 3.1 质量指标
1. **Evidence Recall@Budget**：工作集选中的 `entry_id` 集合覆盖人工标注 `required_evidence_entry_ids` 的比例：
   $$\text{EvidenceRecall} = \frac{|S_{\text{selected}} \cap E_{\text{required}}|}{|E_{\text{required}}|}$$
2. **Forbidden Contamination Rate（越低越好）**：工作集中错误混入已作废约束 `forbidden_superseded_entry_ids` 或导致模型产出过时结论的用例占比。
3. **End-to-End Task Pass Rate**：由固定裁判模型（LLM-as-a-Judge，配合确定性断言 Rubric）对最终回答打分（通过 / 部分通过 / 失败）。

### 3.2 成本与缓存指标（含真实 API 折扣核算）
由于离线逐轮重放可能复用模拟器统计，**前缀缓存命中率必须按字节/Token 级最长公共前缀精确仿真 + 小规模真实 API 抽样核验**：
1. **最长公共前缀命中率（Simulated Cache Hit Ratio）**：
   设第 $t$ 轮序列化后的 Prompt Token 序列为 $P_t$，第 $t-1$ 轮为 $P_{t-1}$（且当前保留至少 1024 tokens 最小缓存门槛）：
   $$T_{\text{read}}(t) = \mathbb{I}[\text{LCP}(P_t, P_{t-1}) \ge 1024] \cdot \text{LCP}(P_t, P_{t-1})$$
   $$T_{\text{uncached}}(t) = |P_t| - T_{\text{read}}(t)$$
2. **标准归一化账单成本（Normalized Cost Index）**：
   以主流 Prompt Caching 典型费率（$c_{\text{read}} = 0.1 \times c_{\text{base}}$，Anthropic 写法含 $c_{\text{write}} = 1.25 \times c_{\text{base}}$；OpenAI 自动缓存为 $0.25\sim 0.5 \times c_{\text{base}}$ 且无写溢价）同时计算两套口径，避免结论依赖单一厂商定价。

### 3.3 算法计算耗时
记录每轮触发上下文组装的 **图更新耗时、向量/BM25 检索耗时、PPR/热核迭代耗时、MMR/DPP 选择耗时**（p50 / p95 / p99）。

## 4. 实验执行步骤与准出（Go / No-Go）门槛

### 执行四步走
1. **Phase 1 — 基准语料构建（1–2 天）**：
   - 基于 [`case.schema.json`](../datasets/case.schema.json) 编写 15 个手工精标多跳/冲突/高熵噪音用例（Suite A/B/C 各 5 个），并从脱敏真实会话导出 5 个长会话（Suite D）。
2. **Phase 2 — 离线检索与缓存模拟器（2–3 天）**：
   - 在本项目中实现纯 Go 评测 Runner：先不调大模型生成，**纯离线跑通 `Evidence Recall`、`Forbidden Rate`、`Simulated Cache Hit Ratio`、`Normalized Cost` 与 `p95 Latency`**。在 20 条长轨迹上把参数（$\alpha, \lambda, \eta, d, \text{Epoch}$）调稳。
3. **Phase 3 — 真实 LLM 端到端对比验证（1–2 天）**：
   - 对表现最好的两组方案（预计 `E4-A` vs `E4-B`）与 `B0`、`B1`、`B2` 一起接入真实大模型 API，对比真实返回的 `Usage.CacheReadTokens` 与 `Task Pass Rate`。
4. **Phase 4 — 准出评审与合入 `gp`**：
   - 满足以下**全部门槛**后，方可将实验代码重构并合入 [`gp`](https://github.com/npc1607/gp)：
     - `E4` 在 Suite A 上的 Multi-Hop Evidence Recall **$\ge$ 85%**（且高于 `B2` 至少 **25 个百分点**）；
     - `E4` 在 Suite B 上的过时约束误触发率 **$< 5$%**；
     - `E4` 在 Suite D 上的 50+ 轮真实含缓存总账单成本相比 `B0` **降低 $\ge$ 45%**，且缓存命中率 **不低于 `B1`**；
     - 纯本地上下文组装 **p95 延迟 $\le 30\text{ ms}$**。
