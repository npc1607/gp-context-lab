## 1. 四类“照妖镜”测试集（对应不同线上故障场景）

做后台压测不能只看常规流量，必须专门构造边界 Case。项目设计了 4 类长会话（50–150 轮）测试套件：

- **Suite A（隐性多跳关联）**：源前提与末尾提问**零关键词重合**（余弦相似度 $< 0.25$），专测 PPR / 热核扩散能否顺着文件依赖链捞回证据。
- **Suite B（约束演进与冲突）**：同一会话内多次推翻技术选型（如 MySQL $\rightarrow$ PostgreSQL），专测结构化账本能否拦截过时方案。
- **Suite C（高熵噪音与复读机风暴）**：中段注入大量 Go panic 堆栈、UUID 与 typo 反复确认，角落里埋入极短核心限制（如“并发上限为 2”），专测 MMR / k-DPP 去冗余，并反证裸 Surprisal 的缺陷。
- **Suite D（真实 `gp.db` 回放）**：导出真实开发会话逐轮回放，核算 **最长公共前缀（LCP）缓存命中率** 与 **真实 API 账单**。

## 2. 8 组单变量消融实验（Control-Variate A/B Test）

就像灰度发布每次只开一个特性开关，实验拆为严格递进的 8 组：

- **3 个基线**：
  - **`B0`（全量历史 + 缓存）**：准确率天花板，给出“裁剪到底值不值得”的成本基准。
  - **`B1`（`gp` 现状）**：`applyObservationMasking(5)` + 5 段自然语言摘要，量化当前缓存击穿与摘要漂移。
  - **`B2`（朴素 RAG）**：近期窗口 + 纯向量 Top-K，暴露多跳漏召回与复读机问题。
- **5 个实验组**：
  - **`E1`**：`B2` + **Budgeted MMR / k-DPP**（验证去冗余贡献）
  - **`E2`**：`E1` + **PPR / 热核 + BM25 RRF**（验证多跳关联贡献）
  - **`E3`**：`E2` + **结构化 `ContextLedger` + ACT-R**（验证抗冲突与长程记忆贡献）
  - **`E4-A / E4-B`**：`E3` + **Epoch 冻结掩码（Epoch=8）**，对比两种 Prompt 拼接顺序的真实账单与准确率
  - **`E5`**：在 `E2` 中注入 **裸 Surprisal**（负对照，实证高熵噪音如何挤占有效上下文）

## 3. 为什么不能让 LLM 直接打 `1–10` 分？—— 三层评判漏斗

直接让大模型打 `1–10` 综合分会导致**阶段混淆**（分不清是检索漏了，还是模型没用好）和**同情分偏差**（回答很长很通顺，但偷偷用了旧方案）。为此项目设计了三层漏斗：

1. **Layer 1 · 确定性检索层评分（纯内存、0 成本、100% 可复现）**：  
   不调 LLM，直接核对进入工作集的 `entry_id` 集合：
   - **Evidence Recall（证据召回率）**：必备证据覆盖比例；
   - **Bridge Completeness（多跳桥接完整度）**：多跳链条是否完整闭合（断一跳即 0）；
   - **Contamination Rate（污染率）**：是否混入 `superseded` 旧规则。
2. **Layer 2 · 确定性输出硬断言（Hard Fail Gate，一票否决）**：  
   类似 CI 里的正则单测门禁。只要回答里出现明确违禁项（如推荐了 `/v1/tasks` 旧接口、推荐了禁用 protobuf tag `12`、放行了 `AGPL-3.0`），**直接一票否决判 0 分**。
3. **Layer 3 · Atomic Rubric 盲测裁判（LLM-as-a-Judge）**：  
   通过 Layer 2 后进入逐条原子清单核验（True/False）：
   - **强制原文摘录（Quote-Grounded）**：裁判判 True 必须摘出待测回答原句，摘不出则自动无效，防裁判脑补；
   - **盲评 + 位置交换（Position Swap）**：隐藏实验组标签，关键对比（如 `E4-A` vs `E4-B`）交换顺序各评一次，两次一致才判优胜；使用固定版本异源裁判模型。

## 4. 后台 Debug 神器：失败归因四象限

将 **Layer 1（检索成败）** 与 **Layer 2+3（回答成败）** 交叉成 2×2 矩阵，可直接定位问题出在哪一层：

| | 回答通过 (`Pass = 1`) | 回答失败 (`Pass = 0`) |
| :--- | :--- | :--- |
| **检索成功** | **象限 I · 理想达标 ✅** | **象限 III · Prompt 编排 / 注意力失效 📐**<br>证据已送达但被位置或噪音淹没 $\rightarrow$ 调 `E4-A` vs `E4-B` 拼接顺序 |
| **检索失败** | **象限 IV · 题目区分度不足 ⚠️**<br>模型靠常识猜中 $\rightarrow$ 需加固或剔除用例 | **象限 II · 上下文选择器失效 🔍**<br>证据未召回 $\rightarrow$ 调 PPR / ACT-R / MMR / 账本抽取规则 |

## 5. 上线前的硬性 SLO 门禁（Go / No-Go）

只有同时跨过以下全部门槛（且通过 McNemar 检验与 1000 次 Bootstrap 95% 置信区间 $p < 0.05$），改动才合入 `gp` 主干：
- **Suite A 多跳召回率** $\ge 85\%$（且高于 `B2` 至少 25 个百分点）
- **Suite B 过时约束误触发率** $< 5\%$
- **Suite D 含缓存总账单** 较 `B0` 降低 $\ge 45\%$，且缓存命中率不低于 `B1`
- **纯本地上下文组装延迟**：**p95 $\le 30\text{ ms}$**
